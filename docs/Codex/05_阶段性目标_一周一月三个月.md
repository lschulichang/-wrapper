# 阶段性目标：一周、一月、三个月

这一份文档不是拿来把人绑死在日程表上的，而是拿来帮助你判断：我现在处在什么阶段，这个阶段最重要的目标是什么，哪些事还不该急，哪些事再拖就会空。很多新人最容易陷入的状态，不是偷懒，而是把完全不同层次的目标同时背在身上。今天想把环境配完，明天想读懂论文，后天想改代码，再后天又想出创新点。最后看起来每天都很忙，但一个稳定台阶都没踩实。

所以这里不用“每天几点到几点做什么”的方式来写，而用阶段目标来写。你可以在每个阶段内自行安排节奏，但必须知道这一阶段最基本的验收口径是什么。因为自由不等于没有边界。对零基础学弟来说，真正有效的自由，是在明确的阶段目标内部自由推进，而不是完全凭感觉飘。

## 一、先把阶段目标的总原则说清楚

阶段目标最怕的是一上来就混层。所以这一部分先把总原则立住：当前阶段先复现、先汇报、先形成闭环，而不是一开始就把创新焦虑压到新人身上。

### 1、先说总原则：当前阶段先复现与汇报，不先卷创新

你未来当然要思考专利、创新点和会议论文，但这些目标必须建立在“主链路已经真的看懂、跑通、讲清楚”的基础上。一个对输入输出还说不清楚、对 run 目录和证据还不敏感的人，太早进入创新讨论，往往会很虚。不是能力不够，而是地基不稳。

所以当前最合理的路线，是先把环境、工作区、smoke、batch、结果阅读和汇报能力扎实做起来。只有当这些动作形成稳定闭环后，你再进入专利、创新点和论文预研，才会更像真实推进，而不是概念上的兴奋。

## 二、第一层台阶，一周内先做到不再发懵

一周目标的核心不是“全懂”，而是从完全陌生走到开始能接手。这一部分会把一周阶段的状态、证据、假进展和保底路径都讲细。

### 1、第一阶段：一周内要达到什么状态

一周目标不是“完全掌握 Splat-Nav”，这句话太大，也太空。一周的合理目标，是完成从陌生到能接手的最小跃迁。也就是说，你应该从“看到工作区发懵”进化到“知道项目是什么、该从哪看起、能做最小检查、能解释一轮最小运行结果”。

#### 1.1 一周阶段的目标状态

到一周左右，你应该能稳定通过 SSH 和 Cursor 进入工作区，知道 `/home/howard/Splat-Nav` 的三层结构是什么，知道 `scripts/` 是 wrapper 层、`splatnav-official/` 是上游源码入口、`runs/` 是结果沉淀层。你应该读过 `00` 到 `04` 的主线部分，尤其是术语、项目全景和快速上手三份文档，并对 `config.yml`、`Splat-Plan`、`run_dir`、`feasible`、`smoke` 这些高频词建立了基本认知。

更进一步，你应该已经做过一次最小环境检查，最好还能完成一次 smoke，至少能读懂一份已有的 smoke run 目录。你不一定已经熟练，但你不能再停留在“只知道目录里有很多文件”的状态。你要能用自己的话说出：这个项目现在主要在复现什么，我第一次应该跑哪条链路，跑完以后先看哪些文件。

#### 1.2 一周阶段的证据要求

这一周真正的证据，不是你说自己“差不多看懂了”，而是你手里至少有一份你自己能解释的 run 目录，或者你能对着现有 run 目录做出可信的口头说明。你还应该能拿出一份简短但结构清楚的汇报：项目做什么、当前工作区由哪三层组成、最小运行输入是什么、最小输出在哪里看、自己目前卡在哪。

如果你能做到这些，就说明你已经不是门外人了。你可能还不会改算法，但你已经有能力进入项目内部继续推进。

#### 1.3 一周阶段最容易出现的假进展

第一种假进展，是文档看了很多，但一条最小命令都没真正跑过，或者连 run 目录都没认真看过。第二种假进展，是命令跑过了，但自己并不知道跑出来的 JSON 和日志是什么意思。第三种假进展，是花很多时间在查各种外部知识，却没有回到当前工作区这条主线。第四种假进展，是已经被论文里的高级词吓住，于是一直在“准备准备再开始”，最后迟迟不进入真正的最小动作。

学会识别这些假进展，你就知道自己是不是在真正前进。

#### 1.4 一周阶段如果进度慢，怎么保底

如果一周内你还没跑通 smoke，也不要慌。最稳的保底策略是先确保三件事：SSH 和工具链已打通；新文档主线已经读明白；至少能跟着师兄现有结果目录解释一遍输入输出和验收逻辑。也就是说，即使自己暂时还没独立跑成，也要先把“看懂”和“复述”做扎实。这个保底状态，依然比漫无目的地乱试要有价值。

#### 1.5 一周阶段如果进度快，可以自然往哪延展

如果你一周内不仅看懂了主线，还能独立跑出一次 smoke，并且会读 JSON 和日志，那么下一步最自然的延展不是立刻造新算法，而是进入 batch 的最小版本，开始形成统计视角。也就是说，你可以开始对比不同方法的可行率和耗时，而不是只停留在“某一条路径跑通了”。

## 三、第二层台阶，一个月内形成标准执行链

到了一个月，目标就不能只停留在认识项目，而要开始稳定地执行、稳定地读结果、稳定地对外表达。这里会把这个阶段最该盯的能力形态单独讲开。

### 1、第二阶段：一月内要达到什么状态

一个月阶段，目标就不能只停留在“知道是什么”。这个阶段更合理的定位，是“能够稳定接项目、能独立完成一条标准执行链、能围绕结果做正式汇报”。换句话说，你应该从“新人入门”进入“可以被放心分配具体任务”的状态。

#### 1.1 一月阶段的目标状态

到一个月左右，你应该已经比较稳地掌握当前工作区的主线文档，并能独立在离线/仿真范围内完成环境检查、一次 smoke、一次小规模 batch，以及对结果目录的基本复盘。你对 `scripts/` 中的核心 wrapper 脚本已经有清晰认识，知道 `run_splatplan_smoke.sh`、`run_official_style_batch.py`、`run_in_tmux.sh`、`visualize_batch_results.py` 分别负责什么。

更重要的是，你应该开始能把项目讲给别人听。这里的“别人”，不是指你讲得多华丽，而是指你能用大白话给组里没那么熟悉这套代码的人解释：这个项目为什么要用 GSplat，为什么当前先做 `Splat-Plan` 离线复现，为什么 wrapper 层和上游层要分开，为什么这次结果可以算成功或不算成功。

#### 1.2 一月阶段的证据要求

一个月阶段的证据，至少应该包括几类。第一，你应该有自己独立完成的标准 run 目录，不止一次最小 smoke，而是至少一轮小规模 batch。第二，你应该能拿出一份正式一点的汇报材料，哪怕只是 Markdown 或 PPT 草稿，也要能讲清主链路、实验设置、结果概览和当前问题。第三，你应该能对一到两个核心上游文件做口头走读，比如 `run_splatplan.py` 和 `splatplan/splatplan.py`，说明它们在全局链路里的位置。

#### 1.3 一月阶段最容易出现的假进展

一个月阶段最典型的假进展，是“实验跑了不少，但没有形成可讲述的结构”。比如你可能有很多图、很多目录，但别人一问“哪个脚本做了什么”“为什么这次方法 A 比方法 B 好”，你答不上来。另一种假进展，是开始急着动大重构、动核心算法，但对原链路的输入输出和验收还没有稳定控制。这样做往往会让自己既失去基线，又增加排错难度。

#### 1.4 一月阶段如果进度慢，怎么保底

如果一个月下来你还没有稳定 batch，不要盲目加压。更稳的做法是先确保：至少有一条标准 smoke 链路完全掌握，至少能读懂并复述一份已有 batch 结果，至少能拿出现有工作区的结构化介绍和汇报提纲。也就是说，哪怕执行深度还不够，表达和理解深度也要先补上。因为在科研和工程里，会讲清楚本身就是非常重要的能力。

#### 1.5 一月阶段如果进度快，可以自然往哪延展

如果一个月内你已经能稳定跑小规模 batch、读懂结果并做汇报，那么最自然的下一步是两条线并行推进。一条线是更深入的上游源码阅读，尤其是 `SplatPlan`、`SafeFlightCorridor`、`GSplatLoader` 和样条优化器相关代码。另一条线是围绕五一前后准备可视化、可汇报材料，开始为专利草案和创新观察积累素材。注意，这里说的是“积累素材”，不是立刻硬写创新点。

## 四、第三层台阶，三个月内开始形成自己的判断

三个月阶段不再只是“我会做”，而要逐渐走向“我会判断、会组织、会提出问题”。这一部分负责把这种能力升级说清楚。

### 1、第三阶段：三个月内要达到什么状态

三个月阶段，才适合谈“逐渐进入研究生式推进”。这个时候，如果前面两级台阶都踩稳了，你就不应再只是一个会跑命令的人，而应该开始具备“理解、执行、表达、改进”四件事并行的能力。

#### 1.1 三个月阶段的目标状态

到三个月左右，你理想中的状态应该是：对当前工作区非常熟，能够独立完成离线/仿真主线的标准执行和复盘；能读懂并讲解核心链路代码；能把一段时间内的实验结果组织成结构清楚的汇报；并且开始对项目可能的工程改进点、实验补强点或研究切入点形成自己的判断。

这里的“自己的判断”不要求你立刻写出顶会论文，但至少应该体现在：你不再只是照着做，而是开始思考哪些地方的实验设计可以更稳，哪些代码入口更值得重构，哪些结果呈现更有说服力，哪些限制条件未来需要补实验或补系统。

#### 1.2 三个月阶段的证据要求

三个月阶段的证据，应该比前两个阶段更成体系。你不仅要有 run 目录和图表，还要有能支撑阶段汇报或专利预研的材料，比如结构化周报、阶段总结、对某个核心模块的代码解读、对某类方法差异的实验观察，甚至一份初步的创新问题清单。也就是说，证据不再只是“我跑了”，还包括“我观察到了什么、我如何解释、我认为哪里值得继续做”。

#### 1.3 三个月阶段最容易出现的假进展

这个阶段最大的假进展，是开始频繁谈创新、谈发论文、谈大改架构，但没有稳定可复现的基线结果，也没有严谨的实验和代码证据支持。另一种假进展，是陷入无休止的读论文和搜资料，却迟迟不把自己的判断落回当前工作区。说得更直接一点，三个月阶段的风险，不再是“什么都不会”，而是“容易开始飘”。

#### 1.4 三个月阶段如果进度慢，怎么保底

如果三个月下来你还没真正进入创新探索，也不必自责。更稳的保底是：把当前工作区的离线/仿真主线做成可长期复用的稳定资产。也就是说，环境稳、脚本稳、结果稳、汇报稳、文档稳。一个项目真正的研究推进，从来都不只靠新点子，也靠稳定基线和清晰证据。你把这些做扎实，本身就是很有价值的工作。

## 五、现实节点、带教策略与长期节奏

除了抽象的阶段划分，项目推进还会遇到现实节点和带教问题。这一部分把五一节点、学弟进度慢时的处理方式，以及带教时该看什么放到一起。

### 1、五一前后的现实节点应该怎么看

你们当前谈到的一个现实节点，是 2026 年 5 月 1 日前后。这种时间节点很有用，但不能理解成“到那天必须把所有东西做完”。更合理的理解是：把它当成一个阶段汇报节点。到那个时间附近，最理想的状态不是“已经投出论文”，而是你们手里已经有比较像样的可视化、可汇报结果，以及对当前工作区和主链路的稳定理解。

如果能在五一前后做到这一点，就已经很不错了。后续围绕专利、创新点和会议论文的推进，才会有真实地基。

### 2、师兄带学弟时，最值得盯住的不是进度，而是能力形态

如果你未来要带这个学弟，你最值得观察的，未必是他某一天是不是看了多少页文档，而是他是不是慢慢形成了几种能力形态。第一，遇到问题会不会先确认上下文，而不是乱试。第二，跑完任务会不会主动找 run 目录证据，而不是只看终端最后一行。第三，说不懂的时候，能不能明确说出自己到底卡在术语、路径、环境、代码还是结果解释。第四，汇报时能不能用自己的话讲清楚，而不是只复述文档原句。

这些能力形态一旦长出来，后面的成长会越来越快。反过来，如果这些习惯一直没形成，就算偶尔跑通一轮实验，也很难真正接住项目。

### 3、最后给学弟的一句话

你不需要在第一周就成为算法高手，也不需要一开始就把整个 Splat-Nav 论文和代码全部吃透。你真正需要做的，是一层一层把台阶踩实。先把门打开，先把地图看清，先做最小动作，先留下证据，先讲明白眼前这一段。把这几件事做好，你就已经在一条非常稳的路上了。

当你愿意这样推进时，这个项目不会再是“看不懂的大工程”，而会变成一个你可以逐步接管、逐步复现、逐步讲清楚、最后逐步做出自己工作的真实项目。

### 4、阶段目标真正要防的，不是“慢”，而是“混”

很多新人一听到阶段目标，会本能地把注意力放在时间上，担心自己是不是太慢、是不是跟不上、是不是别人一个星期做到的自己要两个星期。这个焦虑可以理解，但如果只盯着快慢，很容易把真正的风险看偏。对当前项目来说，阶段目标更应该防的，其实不是慢，而是混。也就是说，你可能看起来动作很多，但阶段边界混了，目标层次混了，评价标准也混了。

比如一周目标本来应该是先把项目地图、最小动作和结果证据站稳，可你却把自己逼进“我是不是应该马上想创新”；或者一个月目标本来应该是能稳定 batch、能看懂结果、能做汇报，可你却还停留在只会看终端最后一行；又或者三个月本来该开始形成研究判断，你却还在反复重新适应环境和路径。这种混乱比慢更伤。因为慢往往还能积累，混则很容易把力气白白耗掉。

所以学弟以后判断自己状态时，先别急着给自己贴“快”或“慢”的标签。更值得问的是：我现在做的事，和我所在阶段真正该做的事，对得上吗？只要这件事对得上，慢一点其实也还是在稳步前进；但如果对不上，再快也可能是在空转。

### 5、一周目标再细化一点：真正该长出来的是哪几种基础能力

前面已经说了一周目标的总体状态，但如果要把它再讲得更能落地，其实可以把它拆成几种基础能力，而不是只看你碰到了哪些文件。第一种能力，是上下文定位能力。也就是你能不能快速确认自己现在在哪台机器、哪个账户、哪个工作区、哪套环境里。第二种能力，是最小阅读能力。也就是你能不能顺着 `00 -> 01 -> 02` 把项目总貌和最常见术语先站稳。第三种能力，是最小动作能力。也就是你能不能在 `04` 的引导下做出环境检查或一次最小 smoke。第四种能力，是最小解释能力。也就是你能不能对着一个 run 目录，把输入、输出和验收讲出个大概。

你会发现，这四种能力都不夸张，但非常硬。因为它们共同构成了“这个人开始能接项目了”的最小形状。如果一周结束时，这四种能力至少已经有了雏形，那就说明这周很值。反过来，如果表面上看了很多内容，可这四种能力都还是空的，那就说明这一周很可能只是热闹。

### 6、第一周给学弟最合理的心理预期，不是“我要全懂”，而是“我要先不再发懵”

这句话我特别想单独拎出来说。因为零基础学弟最容易给自己一个过重的心理包袱，仿佛自己第一周就应该把整个 Splat-Nav 论文、工作区、脚本、结果和代码逻辑全啃透。这个目标听上去认真，其实不现实，也不必要。第一周更合理、也更健康的目标，是先不再发懵。也就是说，你看到工作区时不再完全没有方向，看到 run 目录时不再完全无从下手，听到 `config.yml`、`feasible`、`batch`、`GSplatLoader` 这些词时不再完全发怵。

不要小看这种“先不发懵”的状态。它其实是很关键的一道坎。因为一旦人从“完全混沌”进入“虽然还不熟，但开始能分出层次”，学习速度会明显加快。很多人真正的突破，不是突然聪明了，而是从这道坎跨过去了。

### 7、一月目标再细化一点：为什么这个阶段最重要的是“标准执行链”和“稳定表达”

一个月阶段之所以比一周阶段更难，不是因为内容单纯变多了，而是因为要求开始从“我知道一点”转向“我能稳定地做出来，并让别人听懂”。这就是为什么我会特别强调标准执行链和稳定表达。标准执行链的意思是，你不再只靠偶然状态跑出一轮结果，而是对环境、脚本、run 目录、结果阅读和基础复盘已经形成相对稳定的动作顺序。稳定表达的意思则是，你可以比较平静地把项目主线、当前工作区三层结构、一次 batch 的输入输出和自己当前卡点讲给别人听，而不是每次一开口就散。

这两件事看起来一个偏执行，一个偏表达，但其实是同一件事的两面。执行不稳，表达就会虚；表达不稳，执行往往也说明还没真正吃透。所以一个月阶段最值得盯的，不是今天多跑了一轮还是少跑了一轮，而是你的标准执行链是不是开始成形，你的表达是不是开始不那么飘了。

### 8、一月阶段最适合开始补的，不是“全部源码”，而是“核心链路源码”

到了一个月左右，很多人会开始认真问：那我是不是现在该系统读源码了？答案是应该开始读，但读法很关键。更适合当前阶段的方式，不是立刻把整个 `splatnav-official/` 每个目录都一口气吃掉，而是围绕最常用、最贴近当前执行链的部分去读。比如 `run_splatplan.py`、`splatplan/splatplan.py`、`splat/splat_utils.py`、`SFC/corridor_utils.py` 这些核心链路文件，往往就比一上来横扫所有目录更有效。

原因很简单。你现在不是在做纯源码欣赏，而是在让“我刚刚做过的动作”和“上游实现到底在哪里”对上号。只要这条对号线开始形成，源码阅读就会很有成就感。否则你很容易读了很多文件，却始终找不到自己亲手运行过的那些结果到底从哪长出来。

### 9、一月阶段最值得开始训练的一种能力，是“拿结果做正式汇报”

很多新人会把汇报理解成最后阶段才需要的东西，仿佛等项目做得差不多了，再去想怎么讲。其实对当前项目来说，一个月左右恰恰是开始训练正式汇报能力的好时候。因为到了这个阶段，你通常已经不再是完全空手，已经有了一些 smoke 或 batch 结果、一些 run 目录、一些日志和图表。也就是说，你手里已经开始有材料，而汇报能力本质上就是把这些材料组织成别人听得懂、能接得住的结构。

这类训练越早开始越好。因为它会逼着你把很多含糊的理解说实。比如你如果讲不清 wrapper 和上游的关系，那说明这层你还没真稳；如果你讲不清为什么某一轮 batch 不能算完全成功，那说明你对验收还不够敏感。换句话说，汇报不是展示之外的额外工作，它本身就是一种非常强的理解训练。

### 10、三个月目标真正开始值钱的地方，在于“你开始形成自己的判断，而不是只沿着别人的句子走”

三个月阶段和前面最大的不同，不只是内容更多，而是你和项目的关系开始变了。前面两个阶段，你更多还是在学习已有路线、已有结构、已有证据。到了三个月，真正开始值钱的，是你能不能在已有材料上形成自己的判断。这个判断不一定立刻是创新点，但它至少应该体现为：你开始知道哪些实验值得补，哪些代码值得整理，哪些结果值得重点讲，哪些现象看起来可疑、值得再验证。

这里的关键不在于你是不是一下子提出了多厉害的新方法，而在于你不再只是沿着别人的句子走。你开始能说“我观察到”“我怀疑”“我认为这里更值得继续补”。这种判断力是研究训练真正开始发力的地方。

### 11、三个月阶段最自然的两条延展线：工程化沉淀和研究化观察

如果三个月前面的台阶都踩稳了，后面最自然的延展通常有两条。第一条是工程化沉淀，也就是把当前已经跑顺的离线/仿真主线继续做得更可交接、更可复用、更符合规范。比如继续整理脚本、规范结果、压实文档、补注释、统一入口。第二条则是研究化观察，也就是开始围绕现有结果产生问题意识：不同方法为什么差异是这样，哪些场景更难，哪类约束更敏感，哪些地方值得做更系统的对比。

这两条线并不是冲突关系。恰恰相反，它们互相支撑。工程化沉淀会让你的研究观察站在更稳的基线上，而研究化观察会让你的工程整理不至于变成只讲规范、不碰问题的空工程。对你未来想往大厂规范和科研能力两边一起练，这种双线推进其实非常合适。

### 12、如果师弟一个月后还比较慢，带教的人最该做的不是催，而是帮他重新找到“最小闭环”

现实里完全可能发生这样一种情况：一个月过去了，学弟并没有像理想中那样顺滑地进入 batch 和汇报，而是还在一些基本问题上来回打转。这个时候，带教的人最不该做的往往是单纯催进度。因为很多慢并不是态度问题，而是最小闭环还没真正长出来。你催他往前冲，他只会更容易乱。

更有效的帮助方式，通常是带他重新找到最小闭环。也就是重新确认工具链、工作区、主线文档、最小 smoke、run 目录和解释能力这几个点里，到底哪一个还没站稳。只要把那个最松的环重新扣上，很多后续问题会自己缓解。对零基础转码的人来说，这种“帮他重新找回闭环”的支持，比一味催更有用。

### 13、五一节点最值得产出的，不一定是“结题”，而是“可汇报的阶段成果包”

前面提到了 2026 年 5 月 1 日前后的现实时间节点。这里我想再把它说得更具体一点。对当前项目更现实、更有价值的目标，不一定是到那时“所有东西都做完”，而是能拿出一个像样的阶段成果包。所谓阶段成果包，至少应该包括：一套能讲得清的项目介绍、一份对当前工作区与主链路的稳定说明、一到几轮可复盘的结果目录、几张关键图或汇总表、以及一份能在组会或内部沟通里说得过去的汇报材料。

为什么我特别强调“成果包”这个概念？因为它比“我做了很多事”更有形，也更利于后续接着推进。你们到五一前后如果手里真的有这样一包东西，无论是继续打磨专利、继续补实验，还是让学弟接着做，都会容易很多。

### 14、专利、创新点和会议论文，应该在哪个阶段开始以什么强度进入

这件事非常容易让人焦虑，所以值得说细一点。专利、创新点和会议论文当然是最终方向，但它们进入主线的强度，不应该从第一周就拉满。更合理的节奏通常是这样的：第一周到一个月，主要还是把主链路、输入输出、结果证据和汇报能力做稳。到了一个月后，如果基础已经开始成形，就可以低强度地开始“观察式进入”专利和创新，也就是先积累问题、积累现象、积累能主张的工程与系统价值。到了三个月，如果前面基线和表达都已经稳了，再逐渐把这种观察压成更明确的创新方向或专利表述。

这样做的好处是，不会让创新讨论变成空中楼阁。很多新人一开始一谈创新就发虚，本质上就是因为手里没有足够稳定的事实和结果支撑。你让创新晚一点、但稳一点进入，反而更容易长出真东西。

### 15、这一份 `05` 最适合怎么用：不是偶尔翻一眼，而是每隔几天回来重新定位一次

如果说 `04` 更像行动路线，那么 `05` 更像阶段罗盘。罗盘的用法不是一直盯着它不走，而是走一段回来校准一次。所以这份文档最推荐的使用方式，不是第一次看完就扔一边，而是每隔几天、每完成一轮稍微像样的动作之后，再回来重新定位一下：我现在其实更像一周阶段，还是已经摸到一个月阶段的门口了？我现在最缺的是动作闭环、结果阅读、表达能力，还是开始形成自己的判断？

你只要真的这么用两三次，就会明显感觉这份 `05` 的价值。它不会替你工作，但它会防止你在不同阶段之间乱跳。很多项目推进的痛苦，都不是因为事情太多，而是因为人太容易在不同层次目标之间来回摇摆。

## 六、最后把阶段判断习惯真正留下来

最后这部分不再继续铺任务，而是把整份文档压回一种习惯：会判断自己当前在哪个阶段、该补哪一层、怎样避免看起来很忙却没有沉淀。

### 1、读完整份 `05` 后，最值得留下来的，不是一句“我要努力”，而是一个更稳的阶段判断习惯

最后我想把这份文档压回一句最实在的话。它真正想留下来的，不是鸡血，也不是口号，而是一种更稳的阶段判断习惯。你开始知道，不同时间尺度下，什么叫合理目标，什么又只是看起来很忙；你开始知道，遇到慢的时候该怎么保底，进度快的时候又该怎么自然延展；你也开始知道，带一个零基础学弟，真正该盯的不是表面速度，而是他是不是慢慢长出了能接住项目的能力形态。

只要这种阶段判断习惯开始长出来，这份 `05` 就已经值了。因为复杂项目从来不是靠一天冲刺做出来的，而是靠一段一段踩稳台阶走出来的。台阶不怕高，怕的是踩乱。只要你们一直在帮学弟把台阶踩稳，这个项目就会越做越顺。

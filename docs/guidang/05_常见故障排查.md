# 05 常见故障排查

## 1. 空间不足

症状：安装/下载到一半失败，提示 `No space left on device`。

排查：

```bash
df -hT / /data
```

处理：

1. 大文件统一放 `/data/howard/splatnav`。
2. Conda 缓存和环境放 `/data`。

## 2. tmux 命令找不到

症状：`tmux: command not found`。

处理：

```bash
/data/howard/miniconda3/bin/tmux -V
```

## 3. Conda ToS 报错

症状：`CondaToSNonInteractiveError`。

处理建议：

1. 安装时使用 `--override-channels -c conda-forge`。
2. 避免默认 channel 的 ToS 阻塞。

## 4. CUDA/驱动不匹配

症状：`torch.cuda.is_available() == False` 或运行时 CUDA 报错。

排查：

```bash
nvidia-smi
nvcc --version
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"
```

处理：

1. 不升级系统 CUDA。
2. 优先匹配项目支持的 PyTorch+CUDA 组合。

## 5. LD_LIBRARY_PATH 覆盖了 PyTorch 自带 CUDA 库

症状：报错类似：

`undefined symbol: __nvJitLinkComplete_12_4`  
或明明安装了 GPU 版 torch 但 `cuda_available=False`。

原因：

系统里预设了 `/usr/local/cuda-12.0/lib64`，覆盖了 wheel 内置运行时库。

处理：

```bash
env -u LD_LIBRARY_PATH python -c "import torch; print(torch.cuda.is_available())"
```

长期修复：

1. 项目脚本默认在运行 Python 前 `unset LD_LIBRARY_PATH`（已落地）。
2. 不改系统全局变量，避免影响 ROS 与其他账户。

## 6. gdown 下载中断（SSL EOF）

症状：日志出现 `UNEXPECTED_EOF_WHILE_READING`，大文件/多文件下载中途中断。

处理：

1. 使用 `--continue --remaining-ok` 重试。
2. 在 tmux 中运行长下载任务，防止终端退出中断。
3. 使用 `scripts/retry_gdown_folder.sh` 自动重试。

## 7. gdown 单文件不可访问（权限或访问限制）

症状：`Cannot retrieve the public link of the file`。

处理：

1. 优先走 folder 级下载，不直接按 file id 下载。
2. 若关键文件缺失但 `colmap/sparse` 已齐，使用临时方案：
   1. 从 `colmap/sparse/0` 生成 `transforms.json` 和 `sparse_pc.ply`。
   2. 过滤 `transforms.json` 到现有图片集合，先完成代码链路验证。

## 8. Checkpoint 路径不一致

症状：`No checkpoint directory found at outputs/.../nerfstudio_models`。

原因：配置中的 `output_dir` 是相对路径，运行目录变化后找不到模型目录。

处理：

1. 保持官方目录结构不改；
2. 在运行目录下补 `outputs/.../nerfstudio_models` 软链接到真实 ckpt 位置。

# 06 代码规范与重构原则

## 1. 原则

1. 官方仓库原样保留，不直接破坏性修改。
2. 在外层做工程化封装（scripts/configs/docs/tests）。
3. 重构优先可维护性，不改变论文核心算法行为。

## 2. 目录建议

```text
Splat-Nav/
  configs/
  docs/
  scripts/
  third_party/
  runs/
```

## 3. 编码规范（第一版）

1. 函数职责单一，参数命名清晰。
2. 关键流程添加必要注释（不是逐行注释）。
3. 配置优先参数化，避免硬编码路径。
4. 日志可读、可检索、可复盘。

## 4. 改动记录要求

每次结构性改动记录以下信息：

1. 改动原因。
2. 影响范围。
3. 回滚方案。
4. 是否影响复现结果。
